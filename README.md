# SP-Game — текущий SPA-клиент

Vanilla JavaScript + jQuery, CSS и PHP-точка входа `index.php`.
Клиент использует игровой WebSocket API. Сборщик npm не требуется.

## Контрольная версия до кабинета

Снимок **`pre-cabinet-2026-11-03`** сохраняет рабочий клиент до подключения
отдельного сервиса аккаунтов:

- Метка: `pre-cabinet-2026-11-03`.
- Резервная ветка: `backup/pre-cabinet-2026-11-03`.
- Вход, регистрация и PIN-подтверждение используют прежний игровой WebSocket,
  а не API кабинета. Новый кабинет для запуска этой версии не нужен.
- Игровой сервер всё равно необходим. По умолчанию клиент подключается к
  `wss://server.sp-game.ru`; адрес задаётся в WebSocket-клиенте `js/base.js`.
- Включены текущие страницы, стили, изображения и исходники инструментов
  проверки. Логи, кеши, локальное Python-окружение и секреты не публикуются.

Это снимок клиента, не резервная копия игрового сервера или его MySQL.
Для полноценного возврата совместимый сервер должен сохранять прежний вход
и текущий игровой API. Кабинет и его БД данная метка не изменяет.

## Восстановление без перезаписи работающего сайта

Развернуть метку в **новый** каталог:

```bash
git clone --branch pre-cabinet-2026-11-03 --single-branch \
  https://github.com/SNAK84/sp-game-client-js.git \
  /var/www/spa-before-cabinet
cd /var/www/spa-before-cabinet
git describe --tags --exact-match
```

Для локальной проверки можно использовать встроенный PHP-сервер:

```bash
php -S 127.0.0.1:8081 -t /var/www/spa-before-cabinet
```

Для обычного размещения нужен PHP-обработчик и document root этого каталога
в веб-сервере. Статические ресурсы доступны от корня сайта. Перед переключением
рабочего сайта проверить доступность игрового WSS, вход и загрузку страниц.
Восстановление клиента не требует удаления кабинета или сброса игровых данных.

Не выполнять `reset --hard` или очистку текущего каталога ради восстановления:
сначала проверить отдельную копию и сохранить более новые изменения.

## Проверки

```bash
php -l index.php
find js -type f -name '*.js' -print0 | xargs -0 -n1 node --check
```

Скрипты `tools/check_*.py` — отдельные UI/E2E-проверки. Часть использует уже
открытую тестовую Selenium-сессию, а сценарии с `--execute` могут отправлять
реальные игровые команды. Для восстановления клиента запускать их не требуется.
